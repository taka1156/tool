# tool-from-chat

会話 → ツール → tool 登録、までを一続きで行う。

## 1. 要件を決める

- 「さっきの」「今の」と言われたら、直前の会話で扱った処理（変換・生成・整形など）を題材にする。範囲が曖昧なら 1 回だけ確認する。
- 用途だけ渡された場合は、入力 → 処理 → 出力を自分で組み立てる。
- 1 ツール 1 目的。既存ツール（`python3 scripts/tool.py list`）でできることなら、新規ではなく既存への機能追加を提案する。
- ブラウザ内で完結できるかを確認する。外部 API やサーバーが必要なら、作る前にユーザーに伝える（tool は入力を外部へ送らない方針）。

## 2. 中身を組み立てる

会話のコードをそのまま貼るのではなく、ツール向けに再構成する。

- 入力: テキスト欄 / ファイル選択 + ドラッグ&ドロップ / フォーム
- 設定: 番号付きカード（`① 入力` `② オプション`）。値は `webtools:<ツール名>` に自動保存
- 出力: リアルタイムプレビュー、コピー、ダウンロード
- 例外: 不正な入力やライブラリ読み込み失敗は画面上にメッセージを出す
- 使い方ツアー（driver.js）の手順も書く
- 会話中で出た注意点・制限 → ツアーやヒント文（`.hint`）に入れる

ライブラリのバージョンや仕様など、会話の後で変わっていそうなものは必要なら調べ直す。

## 3. HTML を書く

- tool-style スキルの規約を読む。
- 名前は tool-publish の規則（英小文字・アンダースコア）で決め、`python3 scripts/tool.py new NAME` でテンプレートから作る。表示されたパスのファイルに書く。
- メタ情報（description / tool:name / tool:date）も書いておく。
- ファイルとして直接保存する（チャットに貼ってからコピペさせない）。

## 4. 登録する

tool-publish の手順 4〜9（lint → meta → 動作確認 → build → README → commit/push → 報告）を実行する。
