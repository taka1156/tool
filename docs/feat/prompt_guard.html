    全体の流れ

    すべてブラウザ内のJavaScriptで完結します。サーバー送信・外部API・AIモデルは使っていません（ルールベース）。

    ① 候補抽出正規表現で「それっぽい文字列」を全ルール分拾う
    ② 検証チェックサムや番号体系で偽物を落とす
    ③ 重なり解消同じ箇所に複数ヒットしたら1つに絞る
    ④ 判定最も重い重大度で全体の警告レベルを決める
    ⑤ マスクヒット箇所をプレースホルダーに置換

    入力が止まって200ms後に自動で再実行します（デバウンス）。

    ② 検証ロジックの詳細

    クレジットカード：2段階。どちらも通ったら「実在しうるカード番号」として扱います（実在の確認はしません）。

    • Luhn：右端から1つおきに2倍（9を超えたら9を引く）して全桁を合計し、10で割り切れるか。適当な数字列の約9割はここで落ちます。
    • ブランド判定（IIN＋桁数）：Visa＝4始まり・13/16/19桁、Mastercard＝51–55 / 2221–2720始まり・16桁、Amex＝34/37始まり・15桁、JCB＝3528–3589始まり・16–19桁、Diners＝300–305/36/38/39始まり、Discover＝6011/65/644–649始まり。Luhnがたまたま通った注文番号などをここで落とします。

    マイナンバー：上位11桁に重み（下から1〜6桁目は2〜7、7〜11桁目は2〜6）を掛けて合計し、11で割った余りが0か1ならチェックデジット0、それ以外は「11−余り」。12桁目と一致するかを見ます。

    電話番号：存在確認はできないので、日本の番号体系に合うかで判定します。+81 は 0 に置き換えてから判定。

    • 携帯：070/080/090＋8桁（計11桁）
    • IP電話：050＋8桁
    • フリーダイヤル：0120＋6桁、0800＋7桁
    • 固定：0＋市外局番〜加入者番号で計10桁（0X0 始まりは除外）

    メールアドレス：形式のみ。到達確認（MXレコード照会など）は検査対象を外部に送ることになるため、意図的にやっていません。

    プライベートIP：IPv4形式のうち 10.x / 172.16–31.x / 192.168.x / 127.x だけを残します（各オクテット255超は除外）。

    ③ 重なり解消 → ④ 判定 → ⑤ マスク

    重なり解消：全ヒットを「重大度が高い順 → 長い順」に並べ、すでに採用した範囲と重なるものは捨てます。

    判定：ヒットの中で最も重い重大度で全体を決めます。

↓

    設計方針と限界

    • 見逃しより誤検知を許す：警告ツールなので、迷うものは「要確認」「参考」で出します。
    • 文脈は読まない：ルールベースなので「田中さんの件」が実在の人物かどうかは判断できません。辞書を育てるほど精度が上がります。
    • 検出できないもの：ラベルや敬称のない人名、言い換えられた機密（「例の案件」など）、画像内の文字。
    • 外部に一切送らない：入力本文は保存もしません。保存するのは社内辞書だけ（localStorage）。
